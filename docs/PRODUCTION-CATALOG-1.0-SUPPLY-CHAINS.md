# Production Catalog 1.0 — Поставки, логистика, зависимости
Статус: проектная спецификация v1.0; договорные объёмы и цены настраиваются моделью экономики, не являются константами рецепта.

## Режимы источников (67 SKU без местного рецепта)
1. `farm_or_fishery`: 30 товаров. Поставка ограничена землёй, урожайностью, сезонностью, доступной техникой/персоналом и биологическими ограничениями. Не бесконечная генерация сырья.
2. `extraction_or_utility`: 17 товаров. Для добычи учитываются месторождение, оборудование, энергия и стоимость. Древесина требует лесозаготовки. Термин режима исторический, вода выделена отдельно.
3. `recovery`: 5 видов вторсырья (металлы, стекло, бумага, пластмассы): объём ограничен реальными отходами потребления/производства и возвратов.
4. `system_utility`: 2 SKU воды, объём ограничен инфраструктурой и тарифом, выдаётся только через расчётный источник.
5. `finite_import`: 13 SKU, включая чай, кофе и некоторые технологические компоненты. Импорт имеет лимиты предложения на город/регион/игровой период, задержки, стоимость доставки, внешнюю стоимость, таможенную/налоговую модель и риск срыва.
Все 300 товарных кодов либо имеют фиксированный производственный рецепт, либо один из этих пяти режимов снабжения.

## Складской контракт
- Хранится запас конкретных партий и товаров в минимальных целочисленных единицах.
- Остаток = поступило − списано − зарезервировано − испорчено − реализовано.
- Приёмка по партии, весу и качеству. Гарантии массы, упаковки и единиц на границах API.
- Запасы с ограниченным сроком хранения списываются через FEFO (срок истекает раньше — отгружается раньше).
- Для сырья без срока порчи возможен FIFO или средневзвешенная оценка себестоимости, выбор способа фиксируется бухгалтерской политикой.
- Любое изменение запаса/денег идемпотентно с однозначным transaction_id.

## Коммерческие связи
Предприятие может:
- произвести сырьё само, если владеет подходящим предприятием;
- купить материал у другого реального игрока;
- заключить контракт поставки с ИИ-компанией на тех же условиях;
- купить доступный объём на бирже или оптовой базе;
- приобрести ограниченный системный импорт.

Контракт: стороны, товар, качество, партия/диапазон партий, количество, период, место отгрузки, логистический маршрут, способ оплаты, обеспечение, штраф, условия изменения и отказа. Все цены и количества целочисленны. Двойная продажа резервированного объёма недопустима.

## Граф производства
По данным `PRODUCTION-CATALOG-1.0-RECIPES.json` все рецепты используют только существующие коды, а зависимости ведут к меньшему технологическому уровню. Бесконечные петли «товар → он же как сырьё → товар» отсутствуют. Это формальная гарантия ацикличности, а не доказательство жизнеспособности спроса, окупаемости или отсутствия критических монополий.

## Пример зависимостей
- Сталь листовая (OTHER-009) ← железная руда (RAW-001) и уголь (RAW-002).
- Автокузов (AUTO-021/022) ← сталь листовая.
- Двигатель (AUTO-014) ← сталь листовая + медное сырьё + управляющая электроника.
- Легковой автомобиль (AUTO-001) ← кузов + двигатель + КПП + колёса + стекло + кресла + тормоза + подвеска + ЭБУ.
- Смартфон среднего класса (ELEC-002) ← процессор + дисплей + аккумулятор + корпус + плата + камера.
- Книга (BOOK-001) ← бумага + типографская краска + переплётный материал.
- Йогурт (FOOD-009) ← сырое молоко + культура закваски + фрукты + упаковочный полимер.
- Пиво (FOOD-083) ← ячмень + хмель + пивные дрожжи + технологическая вода + стеклянная бутылка + крышка; соложение считается внутренней стадией пивоварни, пока солод не выделен отдельным SKU.

## Импортный предохранитель
Чтобы NPC не вытеснили игроков: у каждого внешнего SKU есть конечная квота, региональная цена, период пополнения и ненулевое плечо доставки. Значения вычисляются балансировщиком, а не бесконечным магазином. Ограничения спроса и предложения поддерживают развитие отечественных цепочек.

## Недостающая глубина полной игры
После MVP добавятся полупроводниковые фабрики, дополнительные марки стали, фурнитура, точные продукты нефтехимии, автокомпоненты и отдельный солод. В MVP их укрупнение либо явный импорт описаны как осознанная абстракция, а не как скрытая бесплатная поставка.
